1

Think of a parking lot

Imagine 20 parking spots in a row. Each car (a file) needs several spots side by side. Cars arrive (allocate) and leave (release). After a while the empty spots are scattered in small gaps, so a big vehicle may not fit even though many spots are empty in total. That problem is called fragmentation, and this project simulates it.

Replace spots with blocks and cars with files, and you have the project. Nothing touches your real disk: the storage exists only inside the C++ program.

2

Two data structures, two jobs

Member 1

Array of blocks

A row of boxes numbered 0, 1, 2 … Each box remembers: used or free, and which file. It is the complete picture, block by block.

Answers: “What is in block i?” · O(1)
Member 2

Linked list of free gaps

Each node says [start, size] for one run of free blocks. It is a short summary of only the free space.

Answers: “Where is free space, and how big?” · O(F)

Why both? With only the array, finding a gap means scanning every block every time. The list lets a strategy look at just the gaps.

Cost of each operation

OperationTimeWhy
Read storage[i]O(1)An array is one block of memory; the address is computed directly.
First Fit searchO(F)Walks the list; may stop early but worst case looks at every node.
Best / Worst Fit searchO(F)Must look at every free node.
Mark or clear n blocksO(n)One step per block of the file.
Release + mergeO(F)Find the position in the sorted list; merging itself is O(1).
Statistics from the listO(F)One pass over the nodes.

N = total blocks, F = number of free segments, n = size of the request.

6

Viva cheat-sheet

What is the project in one minute?
We represent virtual storage as an array of blocks and keep the current contiguous free regions in a linked list. The simulator processes allocate and release requests, updates both structures, reports free blocks, free segments and the largest free segment, and detects failures caused by fragmentation. We compare First, Best and Worst Fit on identical workloads.
Why can an allocation fail when there is enough free space?
Contiguous allocation needs all blocks in a row. If the free space is split into several gaps, no single gap may be big enough. Example: gaps of 5 and 6 are 11 free blocks in total, but a request for 7 fails.
Why an array and a linked list?
The array shows what is in every block (O(1) lookup). The linked list stores only the free gaps, so a strategy walks F nodes instead of scanning N blocks, and splitting or merging gaps is just pointer changes.
How does release merge neighbouring gaps?
The list is sorted by start. After clearing the blocks we find the previous and next node. If the previous ends exactly where the released run starts, grow it. If the next starts exactly where the run ends, merge it too. Four cases: none, previous, next, both.
First vs Best vs Worst Fit?
First Fit takes the first gap that is big enough. Best Fit takes the smallest gap that is big enough. Worst Fit takes the largest gap. Same workload, same seed, different leftovers. We report what our own experiments show, without deciding in advance which one wins.
What does the consistency check do?
checkConsistency rebuilds every maximal run of free blocks from the array and compares it with the linked list node by node. If they ever disagree, there is a bug. The pages show it as “Consistent”.
What did the web page do and what did C++ do?
All data-structure work (array, list, strategies, statistics, experiments) is in C++. The page sends a request such as /api/allocate?id=A&size=5 and draws the JSON answer.
